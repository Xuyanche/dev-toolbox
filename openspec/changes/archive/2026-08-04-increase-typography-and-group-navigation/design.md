## Context

当前应用以单个 `tools` 数组同时驱动桌面侧栏、移动横向导航和工具页面渲染，默认激活 Base64。状态通过保持所有工具页面挂载、只切换 `hidden` 属性而得以保留。

样式表采用大量局部像素字号，其中品牌副标题、分类标签、字段提示、状态、提示框、按钮和页脚存在 9–11px 设置。字号提升会同时影响侧栏高度、移动导航宽度、分段控件换行和提示框布局，因此需要统一调整，而不能只修改根字号。

## Goals / Non-Goals

**Goals:**

- 用单一分组数据源驱动桌面与移动导航，避免两种导航的分类和顺序漂移。
- 建立明确的界面字号层级，并能审计所有可见文本是否满足 12px 下限。
- 保持现有工具页面挂载策略、键盘能力、响应式断点和本地状态行为。
- 在 320px、390px 和常见桌面宽度下验证字号增大后的完整布局。

**Non-Goals:**

- 不修改工具算法、输入输出行为、路由方式或状态持久化策略。
- 不增加分类折叠、用户自定义排序、搜索或收藏功能。
- 不引入 CSS 框架、图标库或新的运行时依赖。
- 不把桌面侧栏改成可收缩抽屉；移动端仍使用页面顶部导航。

## Decisions

### 1. 使用分组注册表作为导航与页面顺序的唯一来源

将现有扁平工具定义重构为 `ToolGroup[]`。每组包含稳定 id、中文分类名和有序的工具数组；页面渲染通过分组数组扁平化得到工具列表，桌面和移动导航直接按组迭代。数据顺序固定为：

```text
asymmetric     非对称加密
└─ rsa         RSA

digest         摘要算法
├─ md5         MD5
└─ sha1        SHA-1

time           时间工具
└─ timestamp   时间戳

encoding       编码工具
├─ url         URL 编解码
└─ base64      Base64
```

默认 `active` 改为 `rsa`。工具页面仍全部挂载，避免导航重构导致切换后输入状态丢失。

备选方案是在现有数组中增加 `category` 并在渲染时临时分组，但那会依赖遍历时推断边界，容易让分类顺序和工具顺序被独立排序破坏。显式嵌套结构更直接地表达用户要求的层级。

### 2. 桌面分类标题与子工具采用明确语义和视觉缩进

每个分类渲染为带可访问名称的导航分组，分类标题使用非交互元素，子工具继续使用按钮和 `aria-current="page"`。子工具通过缩进、较小图标容器和组间距表达层级；分类标题不进入 Tab 顺序。

侧栏宽度由 252px 小幅增加，以容纳“非对称加密”和“URL 编解码”等增大后的文本，同时保持主内容区域弹性。分类间距会替代当前所有项目统一的 8px 间距。

备选的可折叠分类会增加状态、键盘展开行为，并可能隐藏只有一个子项的分类，不符合本次只重组层级的目标。

### 3. 移动导航保留分组但采用横向分组条

移动端在同一个横向滚动容器中渲染四个不可拆分的组块，每个组块包含 12px 以上分类标签及其工具按钮。组内工具按桌面顺序排列，组块整体允许横向滚动，工具名称不使用省略号裁切。

这比把移动端退化成无分类扁平列表更符合规格，也比多行导航占用更少的首屏高度。分类标签不作为按钮，工具按钮保持现有激活方式。

### 4. 使用字号变量建立可审计的最小层级

在 `:root` 定义并复用以下语义字号：

- `--font-min: 12px`：品牌副标题、分类标题、字段提示、状态和页脚等最低字号。
- `--font-body: 13px`：常规正文、按钮、表单标签和辅助说明。
- `--font-input: 14px`：输入、输出和代码结果。
- 工具标题继续使用现有响应式大字号。

所有现存 9px、10px、11px 声明迁移到合适变量；任何可读文字不得继续显式设置为小于 `--font-min`。装饰性图标中的 `B64`、`M5` 等符号也优先使用 12px，以避免形成难以解释的例外。

备选方案是只在根元素设置较大字号并把全部像素值改成 `rem`，但当前大量组件明确覆盖字号，且全面单位迁移会扩大无关改动。语义变量能以更小范围实现明确下限。

### 5. 字号提升与控件尺寸同步

按钮最小高度、移动导航按钮、侧栏项目、分段选项、输入行高和提示框间距随字号增加 2–4px。允许导航副标题和提示文本换行，禁止固定高度裁切。320px 下操作按钮继续使用弹性换行，表单列继续降为单列。

字号验证分为三层：静态搜索确认 CSS 不存在面向可读文本的小于 12px 声明；组件测试确认分组、顺序、默认项和键盘焦点；真实无头浏览器在桌面、390px 和 320px 视口生成截图进行裁切与横向溢出检查。

## Risks / Trade-offs

- [增大字号会使侧栏内容超过较矮视口] → 允许导航区域纵向滚动，同时固定品牌和隐私提示不遮挡工具入口。
- [移动分组导航变宽，需要更多横向滚动] → 维持清晰组块和完整名称，提供自然触摸滚动，不以缩小字号换取一屏展示。
- [通用最小字号规则可能意外放大纯装饰字符] → 优先让装饰字符也达到 12px；确需例外时使用无文本语义的图形尺寸而非字体模拟。
- [分组与扁平页面列表可能顺序不一致] → 页面列表只从分组注册表派生，并用测试断言桌面、移动和页面顺序。
- [旧测试默认查找 Base64 页面] → 更新测试以 RSA 为初始页面，并显式导航到 Base64 后再验证原有功能，避免削弱算法回归覆盖。

## Migration Plan

这是无持久化数据的前端展示变更。先引入分组注册表并更新导航测试，再迁移字号变量和布局尺寸，最后在多视口下验证。部署仍为静态产物原子替换；若出现布局回归，可直接回滚到前一版本静态资源，无数据迁移或恢复步骤。
