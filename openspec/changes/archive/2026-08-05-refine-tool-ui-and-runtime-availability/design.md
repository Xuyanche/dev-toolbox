## Context

参见 proposal.md。当前 JSON 将复制按钮绝对定位在 textarea 内；JWT 已有成熟的“字段标题 + 外置图标操作 + 固定反馈”结构；对称加密右侧则把带内部状态的普通 `CopyButton` 放进 `Panel` 标题，导致左右标题高度和文本框起点不同。对称加密能力由 `SYMMETRIC_CAPABILITIES` 驱动，适配器已经能够处理 AES-ECB，但 AES 能力表没有暴露该模式。

工具目录目前在 `App.tsx` 中静态声明并直接生成桌面导航、移动导航和内容挂载，首页另有一份独立的静态分类摘要。项目构建为无业务后端的 Vite 静态资源，因此“server 配置”必须是由静态服务器在运行时提供、浏览器启动时读取的公开 JSON 资源。

## Goals / Non-Goals

**Goals:**

- 让 JSON、JWT 和对称加密共享同一套外置字段图标视觉原语，同时保持各工具自己的状态与反馈语义。
- 让对称加密左右文本区域在宽窄视口下结构稳定、对齐且可访问。
- 以现有能力表和适配器路径开放 AES-ECB，不复制密码实现。
- 建立单一工具注册表和经过验证的运行时可用性快照，避免导航、首页和内容区域各自判断。
- 保持静态部署、浏览器本地业务处理及工具切换时的会话状态。

**Non-Goals:**

- 不引入业务 API、账号、权限系统、配置管理后台或配置热推送。
- 不把工具开关细化为算法模式、页面按钮或字段级开关。
- 不将隐藏工具视为安全授权；关闭只影响当前前端部署的可发现性和挂载。
- 不改变 AES、DES、SM4 的密文封装格式，也不增加文件加密。

## Decisions

### 1. 抽取共享字段图标原语，而不是复用 JWT 私有组件

在共享 UI 层提供复制图标、删除图标和统一的标题图标按钮原语，支持可访问名称、title、disabled、焦点与兼容类名。JWT 现有按钮迁移到这些原语但保留 DOM 顺序和 JWT 类钩子；JSON 与对称加密各自组合字段标题、内容框和反馈区。

这样能够统一视觉和交互，又不会把 JWT 特有的 Secret、Claims 切换和填充布局耦合进其他工具。直接导出 `JwtTextRegion` 会把工具私有命名和大量 JWT 布局规则扩散到共享层，因此不采用。

### 2. 文本操作位于字段标题，不再放进 Panel 标题或文本框覆盖层

JSON 输入字段标题右侧放复制图标，textarea 恢复完整内容宽度。对称加密的两个 `Panel` 只显示普通面板标题；每个文本字段使用相同高度的字段标题操作栏。输入字段提供复制、删除，结果字段提供复制。复制反馈使用预留高度的独立区域，操作状态继续使用现有状态区域。

对称加密的文本框在桌面双列中使用同一网格行和高度约束；窄屏恢复自然高度并按输入、结果顺序堆叠。删除仅清空当前明文/密文输入，不清除密钥、模式等配置。

### 3. 参数栏始终保留，模式能力决定禁用状态

参数设置继续使用固定的三列：密钥、模式参数、密文格式。CBC/CTR/GCM 根据能力表显示 IV、counter 或 nonce 的标签、编码和长度；ECB 使用普通但禁用的参数格式控件和输入框，清空旧参数并标明当前模式不使用偏移量，不渲染 `notice-info`。

共享 `Segmented` 增加明确的 disabled 能力或使用等价的不可操作字段集，使无意义的参数编码选择不会保持可操作。相较仅禁用文本框，这能避免辅助技术和键盘用户误以为格式选择仍会生效。

### 4. AES-ECB 通过能力表接入现有适配器

在 AES modes 中加入 `ECB`，参数为空，填充允许 `pkcs7` 与 `none`。执行仍通过 CryptoJS 适配器和既有统一填充层；不增加新的密码库或特殊分支。使用公开 AES-ECB 测试向量验证无填充路径，并增加 PKCS#7 往返测试。

### 5. 运行时配置在 React 挂载前解析为不可变快照

部署文件命名为 `toolbox.config.json`，以页面 base URL 为基准请求并使用 `cache: no-store`，便于静态服务器在不重建 bundle 的情况下更新。配置形状为：

```json
{
  tools: {
    aes: true,
    des: false,
    json: true
  }
}
```

加载器先建立“DES=false、其他注册工具=true”的完整默认映射，再验证远端 JSON。有效的部分映射覆盖默认值；未知键忽略；解析失败、请求失败、缺少 tools 或任一已知键使用非布尔值时，整份远端覆盖被拒绝并返回完整默认映射。请求设置有限超时，失败不阻止应用启动。

`main.tsx` 在配置解析完成后才挂载 `App`；等待期间只显示不包含工具入口的轻量加载状态，从而避免被关闭工具闪现。配置是每次页面加载的一次性快照，不轮询也不热更新。

选择构建时环境变量会要求每次开关都重新构建，不满足部署时修改需求；让各工具自行 fetch 会造成重复请求和呈现不一致，因此均不采用。

### 6. 单一工具注册表驱动所有目录呈现

将工具 ID、分类、名称、短说明、图标、首页摘要和组件工厂集中到一个注册表。配置解析器从注册表派生已知 ID；`App` 过滤注册表得到 enabled groups，并将同一结果用于：

- 桌面导航；
- 移动导航；
- 已启用工具组件挂载；
- 首页分类与工具摘要。

过滤后为空的分类直接省略。只要工具仍启用，现有“全部已启用组件保持挂载、通过 hidden 切换”的方式继续保留页面内状态。选择入口和当前 active 值都经过 enabled ID 校验；若 active 不再有效则回到首页并收起分类。

首页改为接收已过滤的目录数据，不维护第二份工具名称列表。这样新增工具时只需更新注册表和默认策略。

## Risks / Trade-offs

- [配置请求延迟首次渲染] → 配置文件体积保持极小、使用同源静态资源和有限超时；等待阶段只展示稳定加载状态。
- [静态服务器或 SPA base path 不同] → 相对 `document.baseURI` 解析配置 URL，并在子路径构建测试中验证。
- [隐藏工具被误认为权限控制] → 文档明确它只是前端可用性配置；敏感能力仍需部署和网络层安全控制。
- [共享图标原语迁移导致 JWT 回归] → 保留 JWT 可访问名称、类名、DOM 顺序与固定反馈区域，并运行现有 JWT 全量组件测试。
- [ECB 容易被误用] → 模式名称明确展示，继续保留本地开发工具定位；不将 ECB 设为 AES 默认模式。
- [配置错误导致意外暴露 DES] → DES 内置默认关闭，任何无效远端配置都整体回退到该默认，而不是猜测性部分应用。
- [关闭工具后首页文案与分组数量变化] → 首页从同一过滤结果生成，不再依赖固定“六类/十四项”文案。

## Migration Plan

1. 先引入共享图标原语并迁移 JWT，确认现有结构与测试不变。
2. 调整 JSON 和对称加密字段布局，加入 AES-ECB 及领域/组件测试。
3. 建立工具注册表、默认配置与纯函数校验器，再让 App 和 HomePage 使用过滤结果。
4. 在启动入口接入运行时配置加载，并随构建产物提供默认 `toolbox.config.json` 示例。
5. 更新部署文档，说明配置路径、完整工具 ID、默认值、缓存要求和失败回退。
6. 发布时先部署兼容默认配置，再原子替换静态资源。回滚可恢复上一版静态资源；配置文件可保留或删除，旧版不会读取它。
