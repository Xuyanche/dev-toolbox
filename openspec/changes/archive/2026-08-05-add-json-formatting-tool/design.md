## Context

应用是浏览器端 React/Vite 开发工具箱，已有工具通过共享工具注册表进入桌面导航、移动导航和首页。JSON 工具应作为“编码工具”下的独立页面接入，并复用现有页面、面板、状态反馈、复制按钮和响应式布局风格。

用户现在进一步明确：JSON 格式化需要在同一个窗口完成，树形结构展示在右侧，页面使用中文，并且树中任意层级都可以折叠；折叠后要用小框标识折叠内容中包含多少元素。右侧树形结构在视觉上需要保持紧凑，不能因为隐藏控件、复制反馈或不可见行盒导致行距偏大；树区域还需要提供一个“全部折叠/全部展开”的单按钮切换。

## Goals / Non-Goals

**Goals:**

- 严格解析 JSON，并给出中文、可理解、可恢复的错误反馈。
- 在同一个工作窗口中完成 JSON 输入、格式化文本结果和树形查看。
- 在宽视口中使用左右布局：左侧承载输入和格式化/压缩结果，右侧承载树形结构。
- 生成稳定的两空格缩进格式化结果和无多余空白的压缩结果。
- 以树状结构展示对象、数组和标量，并支持复制每个节点对应内容。
- 支持对任意对象或数组层级独立展开/折叠；折叠节点以小框显示其子元素或属性数量。
- 支持一个全局树状态切换按钮：默认显示“全部折叠”并折叠所有可折叠节点；当所有可折叠节点均已折叠时，按钮显示“全部展开”并可一次性展开所有节点。
- 右侧树形结构保持紧凑的代码式行距，节点复制控件、复制反馈和占位元素不得额外撑大主行高度。
- 支持 JSON 字符串转义和去除转义，覆盖带引号字面量与仅包含转义序列的输入。
- 全部处理保持本地、当前页面会话内状态。

**Non-Goals:**

- 不支持 JSON5、注释、尾随逗号、YAML、XML 或自动修复非标准 JSON。
- 不提供 JSONPath/JMESPath 查询、Schema 校验、diff、排序键、语义高亮编辑器或虚拟化大文件查看。
- 不把树节点状态、输入历史或复制内容写入持久化存储。

## Decisions

### Use strict native JSON parsing

领域逻辑使用 `JSON.parse` 作为唯一解析边界，拒绝注释、尾随逗号和其他非标准语法。格式化输出使用 `JSON.stringify(value, null, 2)`，压缩输出使用 `JSON.stringify(value)`。这让工具行为与浏览器运行时一致，并避免引入非标准 JSON 解析规则。

解析失败时清空派生输出和树结果，保留原始输入供用户修正。错误信息使用中文说明解析失败和大致原因，不拼接大量用户输入，避免在反馈区泄露长内容。

### Use one formatting workspace with a right-side tree

格式化模式不拆分为多个页面或先后步骤，而是在同一个工具窗口内展示输入、文本结果和树结构。宽视口下使用两列主布局：左侧为 JSON 输入、格式化结果、复制格式化、复制压缩、清空和状态反馈；右侧为树形结构。

窄视口下左右布局自然堆叠，树形结构跟随文本结果之后显示，保证移动端仍能访问每个输入、按钮和树节点操作。

### Represent tree nodes from parsed values

树状展示直接从解析后的 JavaScript 值递归渲染。对象节点显示属性名和属性数量，数组节点显示索引和元素数量，标量节点显示类型和值预览。根节点默认展开；其他对象和数组节点可以按用户操作独立展开/折叠。

任意对象或数组节点折叠时，其子项不渲染为可见行，同时在该节点行内显示一个稳定的小框，例如“3 项”或“5 个属性”，让用户知道折叠内容的规模。该小框不应挤压节点名称、类型、预览和复制按钮，也不应在展开/折叠时造成布局跳动。

右侧树顶部使用一个全局状态切换按钮，而不是并列的两个按钮。按钮初始文案为“全部折叠”，激活后折叠所有可折叠对象和数组节点；当系统判断所有可折叠节点均处于折叠状态时，按钮文案切换为“全部展开”，再次激活则展开所有可折叠节点。该按钮只改变树的展开状态，不修改左侧 JSON 输入、格式化结果或压缩结果。

树节点主行的视觉高度应由树文本字号和行高决定。折叠按钮、复制按钮、复制反馈、悬浮态占位或状态提示都不应通过额外 `min-height`、行下反馈行或不可见元素撑大每个节点之间的距离；复制反馈应使用不影响树行排版的固定或覆盖式反馈位置，或保持在紧凑且不参与主行间距计算的区域。

### Copy values from their tree node semantics

节点复制使用节点对应值重新序列化：对象和数组复制格式化 JSON，字符串复制原始字符串值，数字/布尔/null 复制其 JSON 表示。这样“复制部件”对开发者最直接：复制容器得到可粘贴 JSON，复制字符串得到其真实内容。

复制反馈放在节点行下方或固定反馈区域，不参与树节点主行尺寸计算，避免“已复制”或失败消息改变树结构对齐。

### Keep formatting and escaping as separate modes

页面使用中文分段控件切换“格式化/树状”和“转义/去转义”。两种模式维护独立输入、输出、错误和复制反馈，避免用户在转义工作流中误触格式化树状态。

转义使用 `JSON.stringify(input).slice(1, -1)` 生成不含外层引号的 JSON 字符串内容；同时提供复制结果。去除转义时，若输入首尾是双引号，则按完整 JSON 字符串字面量解析；否则把输入包裹为字符串字面量再解析，从而支持 `{\"a\":1}`、`\n` 等常见片段。解析失败时提示输入不是有效 JSON 字符串转义内容。

### Integrate through the existing tool registry

新增稳定工具 ID `json`，在 `ToolId`、编码分组工具列表、页面渲染、首页卡片和导航测试中接入。编码分组最终顺序为 `URL 编解码`、`Base64`、`JWT`、`JSON`。桌面与移动导航必须来自同一注册表，避免顺序漂移。

## Risks / Trade-offs

- 大型 JSON 树可能造成渲染卡顿：首版限制交互测试覆盖中等规模输入，并通过单按钮全部折叠和节点级折叠能力减少可见节点；后续如需要再引入虚拟化。
- 折叠计数小框可能和长属性名挤在一起：树行需要使用稳定 grid/flex 尺寸和文本截断/换行策略，避免小框遮挡核心内容。
- 树行视觉密度容易被隐藏按钮或反馈元素影响：实现时需要检查主行盒模型，避免不可见复制按钮、反馈行或占位元素导致节点间距大于左侧输入框的代码行距。
- 复制字符串节点时用户可能期待带引号 JSON 字符串：采用“字符串复制真实值、容器复制 JSON”的规则，并在按钮可访问名称中体现节点类型。
- 原生 `JSON.parse` 错误文案因浏览器不同略有差异：测试应断言可恢复行为和工具自有中文错误前缀，而不是绑定完整运行时错误文本。

## Migration Plan

1. 新增或调整 `src/features/json/` 领域函数与单元测试，覆盖格式化、压缩、树节点值复制、转义和去转义。
2. 调整 `JsonTool` 页面为中文界面，并在格式化模式使用同窗口左右布局：左侧文本工作区，右侧树形结构。
3. 更新树节点组件，支持任意层级独立折叠，并在折叠对象/数组节点上显示子元素/属性数量小框。
4. 在树区域增加单个“全部折叠/全部展开”切换按钮，并确保按钮文案跟随当前整体折叠状态变化。
5. 调整树节点样式，使主行高度由文本行高决定，隐藏控件和复制反馈不额外撑大行距。
6. 将 `json` 接入共享工具注册表、首页和导航，并更新桌面/移动顺序测试。
7. 运行类型检查、单元/组件测试、构建和 OpenSpec 严格校验。
