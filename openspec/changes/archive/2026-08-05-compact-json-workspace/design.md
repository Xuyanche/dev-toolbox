## Context

参见 [proposal.md](./proposal.md) 的动机。当前 JSON 工具以 `mode` 在格式化工作区和独立转义工作区之间切换，分别维护 JSON 输入、转义输入、转义输出和多组反馈状态。格式化分支使用固定 `22` 行文本框，并在顶部提示、模式选择之后渲染双列工作区；主结果复制和树节点复制仍使用文字按钮。JWT 页面也在标题后渲染独立的本地处理提示，但工具箱侧边栏、介绍首页和全局页脚已经提供相同隐私信息。

## Goals / Non-Goals

**Goals:**

- 以一个输入状态和一个工作区承载 JSON 的所有转换操作，避免模式切换和重复输入输出区域。
- 让宽视口中的输入区、操作区和树形区在可用视口高度内稳定布局，并让长内容在区域内部滚动。
- 统一 JSON 主内容和树节点的复制图标、可访问名称、键盘焦点及稳定反馈行为。
- 删除 JSON 与 JWT 顶部重复的隐私提示，同时维持本地处理与安全警告的现有语义。

**Non-Goals:**

- 不改变严格 JSON 解析、格式化缩进、压缩序列化或字符串转义算法。
- 不改变 JSON 树的层级、折叠计数或节点复制值规则。
- 不调整 JWT 解析、校验、生成、Secret 操作、无签名警告或信任状态。
- 不保证低于 1280×768 的桌面视口完全没有页面滚动；窄视口继续使用纵向布局。

## Decisions

### 1. JSON 使用单一输入和单一转换入口

删除 `mode`、独立转义方向选择以及转义输入/输出状态，保留一个 `jsonInput`。格式化、压缩、转义和去除转义分别作为显式按钮直接读取并在成功后替换该输入。格式化与压缩共享严格 JSON 解析结果，并分别选择格式化或紧凑序列化值；转义与去除转义继续调用现有字符串转换函数。

选择显式操作按钮而不是继续保留模式或自动识别，是因为相同文本可能同时是合法 JSON 字符串和用户希望转义的普通文本，自动识别会产生不可预测的转换。保留“压缩 JSON”按钮而只删除“复制压缩结果”，可以维持已有压缩能力并让结果直接可见、可继续编辑。

### 2. 树形结果只表示当前输入的最近一次成功 JSON 解析

格式化或压缩成功后，用同一次解析结果更新树并将根节点设为展开。转义、去除转义、清空及用户手动编辑已经产生树的输入时，使旧解析结果和节点复制状态失效；转换失败时保留用户当前输入，但清除旧树并显示错误。这样右侧树不会继续展示与左侧文本不同的数据。

备选方案是手动编辑或字符串转换后保留旧树，直到下一次 JSON 解析；该方案能减少树闪烁，但会让左右内容失去可信对应关系，因此不采用。

### 3. 主复制操作内嵌输入框，树节点使用同源图标

在文本框包装层右上角放置仅显示图标的复制按钮，并为文本内容预留右侧内边距，避免按钮覆盖输入。该按钮复制当前输入的完整字符串，无需依赖 `parsed`，因此格式化、压缩、转义、去除转义或手动编辑后的内容都能复制。

树节点复制按钮使用与 SHA 摘要和主输入一致的复制图标轮廓，但保留树节点需要的紧凑尺寸、悬停显示和键盘聚焦显示。每个按钮使用描述具体节点或完整输入的 `aria-label` 和 `title`，图标本身对辅助技术隐藏。

备选方案是将主复制图标放在面板标题栏；该位置实现简单，但与被复制内容的关联较弱，也不符合“整合到内容框右端”的现有 SHA 模式，因此不采用。

### 4. 所有 JSON 操作共用一个稳定反馈状态

用单一状态承载格式化、压缩、转义、去除转义、主内容复制和节点复制的成功或失败消息。状态区域在左侧操作区预留固定的最小高度；节点复制不再在树面板顶部插入条件反馈行。节点复制成功消息仍包含节点路径，但不回显节点值。

选择后发生的操作覆盖上一条瞬时反馈，符合工具的线性操作模型，也能避免多组 `StatusMessage` 同时占用高度。备选方案是为转换和复制分别保留状态行；该方案保留更多历史信息，但会继续造成空间浪费和布局跳动，因此不采用。

### 5. 桌面工作区由视口高度约束，移动端恢复自然高度

在可双列呈现且视口至少 1280×768 时，JSON 工作区高度根据动态视口高度减去主内容顶部、工具标题和必要间距计算，并设置合理最小与最大值。两个面板拉伸到相同高度：左侧面板以纵向弹性布局让文本框占据剩余空间，右侧树列表占据剩余空间；textarea 与树列表分别 `overflow: auto`。操作按钮允许在较窄的左列中紧凑换行，但仍位于文本框下方。

在低于双列断点的视口中取消固定工作区高度，恢复单列自然流和现有移动端最大树高度。使用动态视口单位而不是固定 `rows` 作为桌面主高度，能够覆盖浏览器可用高度变化；`rows` 仅作为无样式或移动端的基础尺寸。

### 6. 隐私提示去重不改变安全契约

删除 JSON 与 JWT 标题下方的 `notice-info`，保留两者 ToolHeader 中的本地处理说明，以及侧边栏、介绍首页和全局页脚的全局隐私信息。不在工具底部新增重复的大型提示，避免将同一空间问题移动到页面下方。JWT 的无签名警告、信任状态和所有安全限制保持原位置与样式。

选择依赖已有多层隐私信息而非新增底部提示，是因为底部提示在首屏目标下可见性有限且仍增加文档高度。若未来统一调整全局页脚或侧边栏，应单独评估是否需要通用的紧凑工具级隐私标识。

## Risks / Trade-offs

- [转义和去除转义直接覆盖输入，用户无法在同页同时比较转换前后内容] → 转换前内容仍可由用户自行复制；明确按钮文案和成功反馈，并保持错误时不覆盖输入。
- [用户手动编辑后立即清除树可能造成视觉变化] → 仅在已有树时执行失效，并用空状态明确需要重新格式化或压缩。
- [五个主要操作在较窄的左列中可能换行] → 使用紧凑按钮尺寸和有序换行，确保复制图标不占操作行宽度；不通过缩小触控目标强行维持单行。
- [视口高度计算在浏览器缩放或系统字体放大时不足] → 以最小高度和内部滚动兜底；当内容无法安全容纳时允许文档滚动，优先保证可访问性。
- [删除顶部本地提示可能降低单页隐私信息显著度] → 页面说明继续明确本地处理，全局侧边栏、首页和页脚继续可见；自动化测试继续验证无网络与无持久化行为。
- [图标按钮可发现性低于文字按钮] → 使用统一复制图形、悬停标题、可访问名称、键盘焦点和即时反馈。

## Migration Plan

1. 将 JSON 状态和操作收敛到统一输入、解析树和反馈状态，移除模式与独立转义分支。
2. 增加输入框内嵌复制图标，将树节点复制改为图标，并实现统一反馈与树失效规则。
3. 调整 JSON 双列视口高度、面板弹性布局和移动端回退样式，删除 JSON/JWT 顶部本地处理提示。
4. 更新 JSON、JWT 和工具壳层测试，运行全量测试、类型检查、代码检查、构建与 OpenSpec 严格校验。

回滚时可恢复 JSON 的模式状态、独立转义工作区、文字复制按钮和原固定文本框高度，以及 JSON/JWT 顶部提示；底层转换函数和数据格式无需迁移。
