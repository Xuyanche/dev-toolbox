## Context

当前 `App` 使用 `ToolId` 状态控制十一项工具内容的 `hidden` 属性，并让全部工具组件常驻挂载以保留会话状态；初始工具和展开分类分别固定为 RSA 与 `asymmetric`。桌面和移动端各自渲染品牌区域，桌面分类箭头使用字体字符 `⌄` 配合旋转，字符自身不对称的字形边界和行盒会在旋转时造成视觉中心变化。行为要求见两份 delta spec。

## Goals / Non-Goals

**Goals:**

- 在不卸载现有工具组件的前提下，将介绍首页纳入应用活动页面状态。
- 让桌面和移动品牌区域共享一致、可访问的返回首页行为。
- 用不依赖字体度量的箭头图形和固定几何盒消除对齐偏差及旋转跳动。
- 让首页布局复用现有视觉变量，并在桌面和窄视口保持清晰。

**Non-Goals:**

- 不引入 URL 路由、浏览器历史记录、首页持久化选择或深链接。
- 不把首页做成新的工具分类或改变十一项工具的顺序。
- 不改变桌面单分类展开规则、移动端横向导航方式或工具内部状态模型。
- 不引入图片资源、网络内容或新的运行时依赖。

## Decisions

### 1. 使用可为空的活动工具状态表示首页

将活动状态建模为 `ToolId | null`，其中 `null` 明确代表首页；初始活动工具和初始展开分类都设为 `null`。选择工具时同时设置工具 ID 和所属分类，返回首页时同时清空两者。内容区在 `active === null` 时渲染首页，原有工具列表继续常驻并仅通过 `hidden` 切换。

备选方案是为首页伪造一个 `ToolId` 并加入工具数组，但这会把首页错误地纳入工具导航和分类语义。引入完整路由则超出当前单页内存状态的需要，并会增加历史记录与深链接决策，因此本次不采用。

### 2. 首页作为独立展示组件，分类概览使用只读内容

新增独立首页组件，包含主标题、简短介绍、本地处理说明和六个分类概览。分类卡片用于解释能力范围，进入具体工具仍通过既有桌面或移动导航完成，避免首页再复制一套工具选择状态和焦点顺序。首页只消费稳定的展示数据，不访问网络，也不持有工具状态。

备选方案是让每张首页卡片直接跳转工具，但分类包含多个工具时默认目标不明确，也会制造第二套导航行为，因此不采用。

### 3. 品牌区域使用原生按钮语义

桌面侧栏和移动头部的整个品牌区域改为样式重置后的原生按钮，并提供一致的可访问名称。两者调用同一个返回首页处理函数。原生按钮天然支持 Enter、Space、焦点顺序和禁用无关的交互语义，比在 `div` 上补 `role`、`tabIndex` 与键盘监听更可靠。

品牌按钮保留现有标识与文本布局，并增加与整体视觉一致的 hover 和 `focus-visible` 状态；首页已激活时按钮仍可聚焦，但重复激活只保持首页状态。

### 4. 用固定尺寸 SVG 替换字体箭头

将 `⌄` 字符替换为具有固定 `viewBox` 的内联 SVG，外层箭头盒设置固定宽高、`display: grid` 和 `place-items: center`。旋转施加到固定方形 SVG 或其固定盒上，显式设置 `transform-origin: 50% 50%`，并只过渡 `transform`。分类按钮继续使用 flex 居中，标题文本与箭头盒拥有稳定的纵向中心。

相比调整字体字符的 `line-height` 或相对偏移，SVG 不依赖操作系统字体的字形边界，能够在不同平台和缩放比例下保持相同几何中心。CSS 伪元素绘制边框箭头也可避免字体问题，但更难保持清晰描边和无障碍测试中的稳定结构，因此不采用。

### 5. 测试覆盖状态语义与稳定结构，视觉几何做浏览器核对

组件测试覆盖：首页初始显示、无当前工具、六个分类收起、点击和键盘激活品牌返回首页、工具状态保留、移动品牌入口以及选择工具后的当前项和展开状态。箭头测试确认每个分类使用固定 SVG 结构、展开只改变程序化状态且节点不被替换；实际像素级水平对齐和旋转无跳动在桌面浏览器中核对，因为 DOM 测试环境不执行真实字体与布局渲染。

## Risks / Trade-offs

- [主规格仍可能保留旧的 RSA 默认描述，且另一未归档变更也修改过导航] → 本 delta 完整修改同名默认活动要求；实施前按当前工作区代码和所有活动变更校验，归档时按依赖顺序同步规格。
- [品牌按钮进入键盘焦点顺序会改变首个焦点目标] → 更新键盘导航测试，并确保品牌入口作为返回首页的主要操作排在导航之前。
- [首页增加内容可能延长移动端首屏] → 使用紧凑响应式网格，不使用大图或固定高度，保留移动导航在首页顶部附近可访问。
- [SVG 旋转仍可能因非方形盒或路径偏心产生跳动] → 固定方形 viewBox、对称路径、固定外盒和中心 transform origin，并在展开/收起两态进行浏览器核对。

## Migration Plan

1. 新增首页组件及样式，不接入默认状态。
2. 扩展应用活动状态和品牌按钮行为，保持工具组件常驻挂载。
3. 替换分类箭头结构及样式并更新组件测试。
4. 运行完整测试、类型检查、Lint、生产构建和严格 OpenSpec 校验，并在桌面/移动视口手动核对。

回滚时可恢复 RSA 与 `asymmetric` 初始状态、品牌静态结构及旧箭头标记，并移除首页组件；工具数据和工具内部状态无需迁移。
