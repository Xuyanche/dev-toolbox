## Why

JWT 双列工作区已经稳定了生成与解析模式的整体尺寸，但生成算法仍占用正文、解析端的算法/校验框体仍挤压 Header 与 Payload，并且列级滚动和不确定的网格高度会导致可用空间未被充分使用，甚至无法完整展示常见的格式化 Header。需要把次要控制移出主要工作区、压缩签名状态呈现，并让正文区域真正填满固定高度。

## What Changes

- 保持解析与生成模式现有的相反双列数据流、相同桌面高度及窄屏自然堆叠规则。
- 将 JWT、Header、Payload、Secret 和生成结果等所有复制图标从文本框内部移到对应字段标题行右侧，不再覆盖或挤压文本内容。
- 移除 Header、Payload 和生成结果标题行中的“只读结果”“只读预览”“完整内容与注册 Claim”等辅助说明，为标题栏操作腾出空间。
- 生成模式移除独立的“清除 Secret / 生成新 Secret”按钮行，在“Secret（可选）”标题右侧依次提供“生成”、复制图标和删除图标；复制与删除在 Secret 为空时禁用。
- 解析模式在“Secret（可选）”标题右侧提供复制与删除图标；删除只清空解析 Secret，不影响 JWT 输入或已解析结果。
- 解析模式移除独立注册 Claim 框体，在 Payload 区域标题栏提供“Payload / 注册 Claim”切换；两种视图复用同一正文区域，并由复制图标复制当前视图，当前视图无可复制内容时禁用。
- 将生成模式的“签名算法”移到工作区外的模式操作行右侧，仅在生成模式显示，从而把生成列内空间留给 Header、Payload 与 Secret。
- 解析模式移除签名算法/签名校验框体；算法仍可从 Header 的 `alg` 字段查看，校验状态改为显示在 Secret 下方并替代原 UTF-8 静态说明。
- 将解析 Secret 占位文案改为“UTF-8文本密钥，留空则不做校验”；成功解析后如 Secret 被编辑或删除，立即将旧校验结果标记为待重新解析，避免继续展示过期的有效/无效状态。
- 桌面端让两列填满工作区的确定高度，仅允许文本正文内部滚动；为 Header 分配足以完整展示常见四行格式化 JSON 的最小高度，其余弹性空间优先交给 Payload。窄屏继续使用自然高度堆叠。
- 保留完整 Payload、自定义 Claim、注册 Claim 格式化摘要、签名信任状态、无签名警告、主清空操作及本地敏感数据处理边界。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `jwt-tool`：调整 JWT 文本区复制控件位置、Secret 标题栏操作、解析 Payload/注册 Claim 切换、生成算法位置、解析签名状态呈现及工作区高度分配行为。

## Impact

- 影响 `src/features/jwt/JwtTool.tsx` 的字段标题栏、解析视图状态、Secret 操作、签名状态失效逻辑、生成算法位置与复制目标。
- 影响 `src/styles.css` 中 JWT 标题栏操作、正文空间分配、确定高度网格、Header 最小高度和响应式规则。
- 影响 JWT 组件测试及视觉回归验证；不修改 JWT 解析、HMAC 校验、生成算法、网络行为或持久化边界。
- 不引入新依赖或公开 API 变更。
