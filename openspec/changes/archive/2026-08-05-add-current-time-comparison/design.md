## Context

时间戳页面在 `TimestampTool` 内管理转换表单与当前时间状态，`timestamp.ts` 已提供可将任意有效 `Date` 时刻格式化为 UTC 或带本地偏移 ISO 8601 文本的共享逻辑。MD5、SHA 和当前时间对照区已复用 shell UI 层的紧凑只读值行。转换区当前仍以 `Date.now()` 初始化输入，并为输入和输出各渲染五行文本框；这与时间戳及日期文本通常为单行值的形态不匹配。具体可观察行为见 `specs/timestamp-conversion/spec.md`。

## Goals / Non-Goals

**Goals:**

- 使三种表示来自单个时钟读取，避免同一次渲染内出现跨毫秒的不一致。
- 在不影响现有转换表单状态的前提下进行周期刷新。
- 复用 MD5 已验证的紧凑行布局、图标和复制反馈语义。
- 让转换区以空输入启动，并以真正的单行文本控件减少垂直空间，同时保留完整值操作能力。

**Non-Goals:**

- 不允许用户修改刷新频率、时间戳单位或当前时间显示格式。
- 不改变现有转换区的秒/毫秒单位选择，也不把当前时间值自动写入转换输入。
- 不引入时间库、后端时钟或网络校时。
- 不改变现有转换、交换、复制、格式校验、时区偏移提示或错误反馈语义。

## Decisions

### 使用单个 `Date` 快照驱动三个值

`TimestampTool` 持有一个当前 `Date` 状态，初始渲染时立即创建，此后使用约 1000 ms 的定时器以新的系统时钟读取替换它。每次渲染从该同一 `Date` 派生本地 ISO、UTC ISO 和 `getTime()` 毫秒值。这比为每行分别调用当前时间 API 更容易保证值之间的精确对应。

定时器在组件卸载时清理。每个 tick 重新读取系统时钟，而不是在上一值上加 1000，因此标签页后台节流或系统时钟调整后不会累积偏差。

### 抽取可复用的紧凑只读值行

将 MD5 现有的行结构与复制 SVG 图标抽取为 shell UI 层的通用只读值行，参数包括可见标签、输出可访问名称、复制按钮名称、值和复制回调。MD5/SHA 与当前时间区均使用该元件，保留现有 CSS 类名或提供兼容扩展类名，以避免已有摘要布局回归。

备选方案是在时间戳组件内复制 MD5 JSX 和 SVG。该方案改动较小，但会产生两套后续可能漂移的图标、可访问与禁用状态实现，因此不采用。

### 复用现有 ISO 格式化规则并提供无错误分支的辅助函数

从 `timestamp.ts` 中抽出或导出将有效 `Date` 格式化为指定时区 ISO 文本的辅助逻辑，使转换流程和当前时间区共用同一套偏移、补零和毫秒规则。当前时间来自有效的浏览器 `Date`，因此辅助函数可直接返回格式化文本；用户输入验证仍由现有 `ToolResult` 转换 API 处理。

备选方案是每秒将毫秒值转成字符串后调用两次 `formatTimestamp`。这会构造无必要的输入解析与 `ToolResult` 分支，且不如共享底层 ISO 格式化逻辑直接。

### 使用一个预留高度的复制反馈区

当前时间区在三行之后保留一个 `aria-live` 状态区，复制时记录行标签并生成具体的成功或失败文案。共享反馈避免三个状态节点，预留高度则避免信息出现时推动下方布局。

### 使用真正的单行文本控件压缩转换区

将转换输入状态从 `String(Date.now())` 改为空字符串，并让输入、输出区域渲染原生单行文本控件。时间戳页面可定义局部的单行字段组件或使用等价的轻量封装，复用现有 `.field`、`.field-heading` 与 `.field input` 样式和可访问标签；该调整不修改通用多行 `TextAreaField`，避免其他工具的文本工作区被连带压缩。

原生单行控件会在内容超过可见宽度时提供内部横向滚动，并保持完整 DOM value，因此交换、复制、校验和再次编辑继续使用未截断字符串。输出控件保持只读，偏移提示仍位于控件下方；两列面板及现有窄屏单列回流规则保持不变。

备选方案是继续使用 `textarea` 并设置 `rows={1}`。该方案虽然改动更少，但文本换行、浏览器最小高度和 resize 行为可能使控件超过一行，也不如单行文本控件准确表达此字段的数据形态，因此不采用。

## Risks / Trade-offs

- [每秒更新会使组件持续重新渲染] → 仅更新一个 `Date` 状态，且使用单个低频定时器；不为三行分别建立定时器。
- [系统时区或夏令时在页面打开期间改变] → 每个 tick 从新 `Date` 重新计算偏移，不缓存时区后缀。
- [抽取通用行可能影响 MD5/SHA 的已有样式或测试查询] → 保持已有类名、DOM 顺序、可访问名称和禁用行为，并运行现有 HashTool 测试与全量回归。
- [定时刷新恰好发生在复制交互附近] → 复制回调使用用户激活时当前渲染行所持有的完整字符串，反馈中指明被复制的行而不回显整个值。
- [单行控件无法同时展开显示很长的 ISO 或自定义日期文本] → 保留完整 value 和原生水平滚动/选择能力，并用长值交换、复制与窄屏测试验证不存在数据截断。
- [新增局部字段封装可能与通用字段样式漂移] → 复用既有 `.field` 结构和输入样式，只增加时间戳页面所需的最小类名，不修改共享多行字段行为。

## Migration Plan

1. 增加并测试可复用的 ISO 格式化和紧凑输出行。
2. 在时间戳页面接入时钟状态、三行对照值与复制反馈，再补齐响应式样式和回归测试。
3. 将转换输入初始化为空并替换输入/输出多行控件为局部单行字段，增加空初始状态、长值完整性及桌面/窄屏紧凑布局测试。
4. 若发现回归，可独立回退单行转换字段，或整体回退当前时间功能区、通用行抽取与格式化导出；该变更不包含持久化数据或迁移状态。
