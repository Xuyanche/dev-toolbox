## Context

参见 [proposal.md](./proposal.md) 的动机。当前 MD5 分支使用两个独立 `Panel` 展示大小写摘要，并通过共享的文字 `CopyButton` 执行复制；SHA 分支已经具备紧凑摘要行、结果框内嵌图标复制按钮和稳定反馈区域。两者位于同一个哈希工具组件和样式体系中，因此需要复用视觉模式，同时避免改动摘要计算及 SHA 已有行为。

## Goals / Non-Goals

**Goals:**

- 让 MD5 大小写摘要采用与 SHA 一致的紧凑行结构和内嵌图标复制交互。
- 在桌面和窄屏中保持摘要标签、完整内容与复制操作清晰、稳定且可访问。
- 尽量复用摘要结果的结构和样式语义，避免 MD5 与 SHA 后续视觉规则继续分叉。

**Non-Goals:**

- 不调整 MD5 或 SHA 的摘要实现、编码规则和输出格式。
- 不改变输入区、算法警告、清空行为或 SHA 算法组的排列。
- 不引入新的图标库、剪贴板依赖或网络行为。

## Decisions

### 1. 将摘要行视觉结构提炼为 MD5 与 SHA 可复用的模式

MD5 结果使用一个结果组，其中包含固定顺序的小写和大写两条摘要行。实现时复用或泛化 SHA 已有的“标签 + 摘要框 + 框内复制图标”结构与样式，使相同的视觉约束由同一组摘要行规则表达。

选择共享摘要行模式，是因为 MD5 和 SHA 的区别只在算法名称与结果长度，交互语义一致。备选方案是复制一套 `md5-*` 样式；该方案短期改动较小，但会产生两套需要同步维护的尺寸、焦点和响应式规则，因此不采用。

### 2. 复制控件使用内嵌图标按钮与稳定反馈区域

MD5 不再使用面板标题右侧的文字复制按钮，而在每个摘要内容框右端渲染与 SHA 一致的复制图标控件。按钮保留 `aria-label`、`title`、键盘焦点样式及禁用语义。复制动作始终读取完整摘要值，不依赖视觉换行或截断后的文本。

复制成功或失败反馈放入预留高度的状态区域，或者使用不会参与摘要行重排的现有反馈机制，避免按钮状态变化导致行位置移动。备选方案是在图标旁临时显示“已复制”文字；该方案会改变内容框宽度并造成视觉跳动，因此不采用。

### 3. 使用可收缩内容列保证窄屏布局完整

摘要行保持紧凑的标签列与可收缩的内容列；内容框允许长十六进制字符串安全断行，复制图标列保持固定宽度。窄屏下优先收缩或换行摘要内容，不将复制按钮移出结果框，也不产生页面级水平滚动。

选择保持相同信息顺序而非在窄屏拆成多层控件，是为了维持用户要求的同一行视觉关系。对于极窄视口，可通过缩小标签列和内容安全断行保持操作可用。

### 4. MD5 复制反馈状态与计算结果生命周期保持独立

MD5 的复制状态按大小写摘要区分，并在重新计算或清空结果时复位；计算结果仍由现有 MD5 结果状态驱动。这样可以避免某一行的反馈错误地出现在另一行，同时不改变计算、替换与清空的现有流程。

备选方案是继续复用通用 `CopyButton` 的内部反馈，但其现有可见文字和面板标题位置不符合本次布局要求，因此采用摘要行级图标复制状态。

## Risks / Trade-offs

- [泛化 SHA 样式可能意外改变 SHA 页面] → 保留 SHA 当前尺寸与类名兼容性，并以 SHA 现有组件测试和快照/DOM 断言验证无回归。
- [32 位 MD5 内容较短，过度复用 SHA 长摘要断行规则可能产生多余留白] → 共享结构约束，但允许 MD5 结果组使用内容驱动的紧凑高度。
- [图标按钮没有可见文字可能降低可发现性] → 提供统一复制图标、悬停提示、明确的焦点样式和复制反馈。
- [剪贴板失败反馈在紧凑布局中挤压内容] → 为反馈预留稳定空间或使用不改变摘要行尺寸的反馈呈现。

## Migration Plan

1. 将 MD5 的两个结果面板替换为单个紧凑结果组，并接入共享摘要行结构和复制状态。
2. 泛化或复用 SHA 摘要行样式，补充 MD5 的桌面、窄屏、复制和清空测试。
3. 运行哈希组件测试、全量测试、类型检查、代码检查和构建，确认 SHA 与其他工具无回归。

回滚时可恢复 MD5 原有的两个结果面板及文字复制按钮；摘要计算数据结构无需迁移。
