## Context

仓库目前只有 OpenSpec 配置，没有既有应用或技术栈约束。该变更需要从零建立一个静态前端，并横跨文本编码、摘要、Web Crypto、严格日期解析、统一交互和测试。具体用户可见行为以五份 capability spec 为准。

应用处理的内容可能包含私钥或敏感文本，因此运行时不能依赖后端请求、远程计算或浏览器持久化。目标运行环境是支持 ES2022、Clipboard API 和 Web Crypto API 的现代桌面及移动浏览器；生产环境应通过 HTTPS 提供静态资源。

## Goals / Non-Goals

**Goals:**

- 建立模块清晰、可单独测试的纯前端架构，使每种转换算法与 UI 状态解耦。
- 对字符集、RSA 参数、时间单位、自定义格式、ISO 8601 和时区作显式约定，避免依赖浏览器隐式转换。
- 在不牺牲私钥生命周期控制的前提下，提供一致的复制、清空、错误和成功反馈。
- 产出无需服务器运行时的静态构建结果。

**Non-Goals:**

- 不提供账号、云同步、历史记录、密钥托管或任何服务器端能力。
- 不把该 RSA 页面定位为证书管理器、文件加密器或生产级密钥保险库。
- 不支持任意时区数据库、自然语言日期解析、Base64 文件处理或流式大文件摘要。
- 首版不支持 Base64 URL-safe 变体、HMAC、SHA-2 工具页或旧式 RSA PKCS#1 v1.5 加密。
- 不要求安装型 PWA；“离线可操作”仅指静态资源加载完成后，所有功能不再依赖网络。

## Decisions

### 1. 使用 Vite、React 和 TypeScript 构建单页静态应用

React 组件负责工具壳与各工具页面，纯 TypeScript 模块负责算法适配、格式校验和错误归一化。工具注册表提供导航元数据和页面组件，使新增工具不需要修改多个分支。样式使用普通 CSS 和设计变量，避免为这个小型应用引入大型组件库。

选择理由是 React 能清晰管理 RSA 多区域状态和跨尺寸导航，Vite 提供简洁构建链，TypeScript 能约束工具模式、时间单位和操作结果。备选的原生 DOM 实现依赖更少，但随着 RSA 和日期校验状态增加会产生较多手工状态同步；Vue 同样可行，但仓库没有既有偏好，采用更通用的 React 生态。

### 2. 算法层保持纯函数或窄接口

代码按 `features/encoding`、`features/hash`、`features/rsa`、`features/timestamp` 和 `shell` 分区。编码、摘要和日期转换暴露不操作 DOM 的函数；RSA 通过一个只包装 Web Crypto 的异步服务暴露结构化结果。UI 只负责收集显式选项、调用能力模块并展示结果。

这比把所有逻辑直接写进页面组件更易测试，也避免相同的 UTF-8、Base64、PEM 和错误处理逻辑重复出现。

### 3. 优先使用平台密码能力，MD5 使用审计友好的小型依赖

SHA-1 和 RSA 使用 `globalThis.crypto.subtle`。MD5 不受 Web Crypto API 支持，因此使用维护活跃、浏览器兼容且可树摇的纯 JavaScript 摘要库，仅导入 MD5 实现。依赖在构建时打包，不从 CDN 动态加载。

备选方案是自行实现 MD5，但密码与字节算法的手写实现增加正确性和维护风险；另一个备选是让所有摘要都使用第三方库，但 SHA-1 已有标准平台实现，没有必要扩大依赖面。

### 4. RSA PEM 作为可移植的源密钥材料

生成流程使用可导出的 2048 位密钥材料，公钥导出为 SPKI PEM，私钥导出为 PKCS#8 PEM。执行不同操作时，将相同 DER 材料按 RSA-OAEP/SHA-256 或 RSA-PSS/SHA-256 导入为具有最小必要 usage 的 `CryptoKey`：

```text
SPKI public PEM ─┬─ import RSA-OAEP → encrypt
                 └─ import RSA-PSS  → verify

PKCS#8 private PEM ─┬─ import RSA-OAEP → decrypt
                    └─ import RSA-PSS  → sign
```

签名固定使用 32 字节盐值。2048 位 RSA-OAEP + SHA-256 的最大明文长度为 190 字节，UI 在 UTF-8 编码后预检字节数。密钥和结果只存于 React 内存状态，不写入 Web Storage、IndexedDB 或日志。

备选方案是分别生成加密和签名密钥对，但会让用户管理四把密钥且不符合单组 PEM 的预期；支持 PKCS#1 PEM 或 PKCS#1 v1.5 算法可提升兼容性，但会扩大解析范围并引入过时参数，因此不纳入首版。

### 5. 自定义格式与 ISO 8601 使用独立的严格解析路径

自定义模式使用小型格式编译器，仅识别 `YYYY`、`MM`、`DD`、`HH`、`mm`、`ss`、`SSS`；其余非字母数字字符按字面分隔符处理，未知字母标记直接报错。格式编译为字段描述和锚定正则表达式，反向解析后执行字段范围、实际日历日期和格式化回读校验。

ISO 8601 模式不复用自定义 token 猜测，而使用单独的锚定语法解析器，接受日历日期以及以大写 `T` 分隔的时分秒、可选三位毫秒、可选大写 `Z` 或 `±HH:mm` 偏移。解析结果先形成经过范围校验的结构化字段，再计算绝对时间：`Z` 使用零偏移，显式偏移从本地字段中扣除，未带偏移的日期时间使用界面选择的 UTC 或浏览器本地时区；仅日期输入补齐为 `00:00:00.000`。

ISO 输出采用单一规范形式。UTC 输出为 `YYYY-MM-DDTHH:mm:ss.SSSZ`；本地输出为 `YYYY-MM-DDTHH:mm:ss.SSS±HH:mm`，其中偏移取目标时刻的实际浏览器本地偏移。这样毫秒时间戳经过 ISO 格式化和反向解析可以无损往返。

UTC 使用 UTC getter/constructor，本地模式使用本地 getter/constructor。对夏令时跳跃造成的不存在本地时间，回读校验会拒绝；对回拨产生的重复本地时间，采用浏览器 `Date` 构造器解析出的较早偏移，并在结果旁展示最终时区偏移。显式 ISO 偏移表示绝对时刻，不受浏览器本地夏令时规则影响。

备选的 `Date.parse` 对无偏移输入和非标准日期的行为不够显式，无法满足严格校验；完整日期库可以覆盖 ISO 周日期、序数日期、持续时间、区间和 IANA 时区，但这些不在当前范围，引入它会增加包体与语义兼容负担。

### 6. 工具状态隔离且不默认持久化

每个工具组件维护自己的输入、结果和瞬时反馈。导航切换时组件状态可在当前页面会话中保留，但页面刷新后全部清空。清空只作用于当前工具。交换操作只出现在真正双向的 Base64、URL 和时间转换页面，并同时交换与重新验证相关字段。

采用内存状态比浏览器存储更符合本地敏感数据边界。若未来需要偏好持久化，应只保存非敏感显示设置，并单独修改规格。

### 7. 统一结果与错误模型

能力模块对预期的输入问题返回带稳定错误类别的结果；不可预期异常在 UI 边界转成通用失败信息，开发构建可保留诊断细节。复制操作具有独立成功/失败状态，不会覆盖转换错误。所有状态通过可访问的 live region 呈现，焦点不会因计算完成而被强制移动。

备选的直接抛出并显示原始浏览器异常会泄露实现细节，而且不同浏览器文案不一致，不利于测试和用户修正输入。

### 8. 分层验证

使用 Vitest 测试纯函数和已知算法向量，使用 Testing Library 验证主要交互、键盘可达性和反馈状态；关键 RSA 测试执行真实 Web Crypto 往返。构建检查验证 TypeScript 与静态产物，浏览器级烟雾测试覆盖导航、窄视口和剪贴板失败降级。

## Risks / Trade-offs

- [MD5 第三方实现可能带来供应链或正确性风险] → 固定依赖版本、仅导入所需模块，并以公开标准向量覆盖空文本、ASCII 和 Unicode 输入。
- [Web Crypto 与 Clipboard API 在非安全上下文或旧浏览器不可用] → 启动时进行能力检测，禁用受影响操作并给出 HTTPS/浏览器要求，不静默降级到不安全密码实现。
- [RSA 私钥会以可复制明文出现在页面] → 默认不持久化、不记录日志，持续展示安全提示，并把工具定位为开发用途而非安全存储。
- [RSA 无法加密长文本] → 按 UTF-8 字节预检 190 字节上限并显示当前长度；不自动截断或悄悄改用其他算法。
- [本地时间受设备时区和夏令时规则影响] → 始终标明 UTC/本地模式和解析后的偏移；拒绝不存在的本地时间，并记录重复时间的解析规则；带显式 ISO 偏移的输入直接按偏移计算。
- [ISO 8601 标准还包含周日期、序数日期、持续时间和区间等形式] → 页面明确称为“ISO 8601 日期时间”模式并展示支持示例，不暗示覆盖标准的所有数据类型。
- [有限自定义格式标记不覆盖所有日期表示法] → 在格式输入附近展示支持列表和示例；未知标记立即报错，未来通过扩展编译器增加能力。
- [工具切换保留内存状态会让敏感内容停留更久] → 提供显眼的单工具清空操作，并在页面刷新时完全丢弃状态；不实现后台持久化。

## Migration Plan

这是全新应用，无现有用户数据或 API 需要迁移。实施时先建立前端和测试基础，再按独立能力模块交付，最后接入统一工具壳并生成静态构建产物。

部署采用静态资源的原子版本发布，并配置 HTTPS。回滚只需将托管目标切回前一个静态构建版本；由于没有数据库、服务端状态或持久化客户端数据，不需要数据回滚步骤。
