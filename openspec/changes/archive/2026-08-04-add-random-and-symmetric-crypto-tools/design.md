## Context

当前应用是 Vite + React + TypeScript 的纯前端工具箱。`src/shell/App.tsx` 以静态分组定义渲染同一份桌面和移动导航，并通过 `hidden` 保留各工具的会话内组件状态。现有散列与 RSA 功能已依赖 Web Crypto API，但浏览器 Web Crypto 不覆盖 DES、SM4，也不能直接表达本变更要求的全部模式/填充组合。

随机和密码学输入均可能包含敏感信息，现有“完全本地处理”的产品约束必须保留。详细可观察行为以四份 delta spec 为准。

## Goals / Non-Goals

**Goals:**

- 为随机数和对称密码建立与 React 表单分离、可单元测试的纯 TypeScript 领域层。
- 用统一字节接口封装不同算法实现，集中处理编码、参数兼容矩阵和错误映射。
- 使用密码学安全随机源并消除整数范围映射中的取模偏差。
- 复用现有应用壳、面板、状态和复制交互，同时保证桌面和移动导航由同一数据源产生。

**Non-Goals:**

- 不提供密钥派生、口令转密钥、密钥保存、文件加密、流式大文件处理或服务端密码接口。
- 不声明 DES 适合新系统，也不提供 3DES。
- 不实现骰子修正值、保留/重掷规则、随机种子或可复现伪随机序列。
- 不改变现有 RSA 默认活动工具；新增分组虽排在 RSA 前面，首次加载仍按已有规格打开 RSA。

## Decisions

### 1. 将每个新增子工具作为独立、常驻挂载的功能组件

新增 `dice`、`random-number`、`symmetric` 功能目录。AES、DES、SM4 共享一个参数化 `SymmetricCryptoTool` 组件，但在导航中创建三个独立实例并传入算法标识；骰子与随机数各自使用独立组件。`ToolId` 和 `ToolGroup` 扩展后继续由同一 `toolGroups` 数组驱动桌面导航、移动导航和内容区。

这样既延续现有状态保留语义，又避免复制三套几乎相同的密码表单。备选方案是为每个算法复制完整页面，初始实现直观但很容易使模式校验和错误文案漂移，因此不采用。

### 2. 随机整数使用拒绝采样，所有随机工具共享安全随机模块

建立基于 `crypto.getRandomValues` 的随机字节源。整数生成把目标区间映射到能够无偏覆盖它的无符号采样空间，并丢弃落在最大整倍数之外的样本；骰子调用同一闭区间整数函数。浮点数由随机 53 位有效数构造 `[0, 1)` 均匀值，再缩放到 `[min, max)`。

整数唯一批次在可用区间较小时采用部分 Fisher–Yates/索引交换映射，避免高占用率下反复碰撞；浮点唯一批次用 `Set<number>` 去重并设置防御性尝试上限。单次随机数批量上限在 UI 和校验层统一设为 10,000，防止意外冻结页面。

使用 `Math.random()` 的实现更短，但不满足本地密码学安全随机源的规格，也不适合作为骰子与随机数模块的共同基础。

### 3. 骰子表达式解析为规范化的数量映射

解析器先按 `+` 分项，再以完整匹配的 `数量 d 面数` 语法解析，忽略外围空白和 `d` 大小写，仅接受白名单面数。重复项（例如 `1d6 + 2d6`）合并为 `3d6`。解析成功时一次性替换可视状态；任何一项失败时返回结构化错误并保持旧状态。

可视控件和文本框都读写 `Record<DieSides, number>`，投掷结果则保存为按白名单面数排序的 `{ sides, values[] }[]` 与派生总和。选择这种单一规范模型可避免双向同步产生两个事实来源。

### 4. 对称密码采用能力矩阵和算法适配器

领域层定义统一的字节接口：算法适配器接收操作、模式、填充、密钥、IV/计数器/nonce 与输入 `Uint8Array`，返回 `Uint8Array`。一个声明式能力矩阵决定界面可选项、必需参数、分组大小和密钥长度：

| 算法 | 密钥长度 | 模式 | 填充 | 模式参数 |
|---|---:|---|---|---|
| AES | 16/24/32 字节 | CBC、CTR、GCM | CBC: PKCS#7/None；CTR/GCM: None | CBC IV 16 字节；CTR counter 16 字节；GCM nonce |
| DES | 8 字节 | ECB、CBC | PKCS#7/None | ECB 无；CBC IV 8 字节 |
| SM4 | 16 字节 | ECB、CBC | PKCS#7/None | ECB 无；CBC IV 16 字节 |

实现阶段优先复用 Web Crypto 的 AES 能力，并为 Web Crypto 无法表达的无填充 AES、DES 和 SM4 选择体积可控、有浏览器构建、许可证兼容且有已知向量测试的库。所有第三方实现隐藏在算法适配器后，并在锁文件中固定精确版本；依赖引入前用 NIST/标准公开测试向量和往返测试验证实际模式语义。相比自行实现分组密码，这一方案显著降低密码原语实现错误；相比把三种算法交给一个未经验证的大型库，适配器允许逐算法替换和审查。

GCM 解密只有认证标签验证通过才返回明文。CBC/ECB 无法认证，因此解密成功只表示编码、长度和填充校验通过；界面不会宣称数据真实性。

### 5. 编码和校验在执行密码操作前完成

新增严格 HEX/Base64 编解码器或扩展现有共享字节工具：HEX 必须为偶数个有效字符；Base64 必须是规范的完整编码，不静默忽略非法字符。明文使用 `TextEncoder`，成功解密后用严格 UTF-8 `TextDecoder`。密文输出按用户选择编码。

表单状态变化先通过能力矩阵移除不兼容选项，再在提交时形成已校验命令。错误按字段分类（编码、长度、模式参数、块对齐、认证/填充失败），UI 只显示安全且可操作的信息，不泄漏堆栈。

### 6. 测试以确定性随机注入和标准密码向量为核心

随机领域函数接受可注入的字节源，生产环境绑定 `crypto.getRandomValues`，测试使用固定序列覆盖拒绝采样、上下界、碰撞与失败路径。密码适配器使用每种算法/模式的已知向量，再补充 UTF-8 往返、错误密钥长度、错误 IV、无填充分组对齐和 GCM 认证失败测试。组件测试覆盖默认值、参数联动、导航顺序、状态保留和可访问名称。

仅做随机分布的统计断言容易产生偶发测试失败，不能替代确定性边界与拒绝采样测试，因此不将其作为主要验收手段。

### 7. 桌面导航使用单展开分组状态

应用壳新增 `expandedGroup` 状态，初始值为当前默认工具 RSA 所属的 `asymmetric`。桌面分类标题改为带 `aria-expanded`、`aria-controls` 的按钮；展开一个分类时收起其他分类，选择工具时确保其所属分类保持展开。移动端继续使用现有横向完整分组导航，不复用桌面折叠状态。

单展开方式比允许任意多个分组同时展开更能稳定控制侧栏高度，直接解决工具增多后的滚动问题。收起区域从布局和焦点顺序中移除，但工具组件仍在内容区常驻挂载，因此不会破坏跨工具状态保留。

### 8. 共享面板标题和随机工具使用紧凑布局

`Panel` 继续作为全局面板入口，统一通过 `.panel-heading h3` 提升字号、字重并改用界面正文无衬线字体，取消当前过小的等宽全大写观感。该调整作用于所有工具页面，不逐页覆盖。

骰子表达式作为 `Panel.aside` 放到“选择骰子”标题右侧，桌面最大宽度约为面板的四分之一，窄视口回流到标题下方；骰子数量控件改为固定紧凑列宽。骰子初始状态由空映射改为只有 d6 数量为 1，表达式状态从同一映射派生为 `1d6`。

随机数生成设置让字段提示保留在输入区内部的固定结构中，避免“生成数量”的提示增加整列高度后破坏底部对齐。两个结果面板均把复制和清空操作放在统一的操作组中；清空只移除结果和结果状态，不重置配置。

## Risks / Trade-offs

- [DES 和 SM4 需要第三方浏览器密码实现，可能增加包体积或供应链风险] → 在任务中先完成依赖审查，固定版本、检查许可证和浏览器产物，并用标准向量将库封装在可替换适配器后。
- [DES 本身已不安全] → 在工具页持续显示显著警告，定位为遗留互操作，不提供任何“推荐”措辞。
- [CBC/ECB 不带认证，错误参数有时可能产生看似有效的明文] → 明确模式性质；严格验证填充和 UTF-8，但不把成功解码描述为真实性验证。
- [大量唯一值会消耗内存和阻塞主线程] → 限制单批 10,000，并在生成前拒绝不可能的唯一整数请求。
- [各密码库对 padding、GCM 标签拼接或计数器语义可能不同] → 统一适配器数据约定，使用已知向量锁定输入输出格式，不直接把库对象暴露给 UI。
- [随机 API 在不安全或旧浏览器上下文不可用] → 沿用全局浏览器能力提示，并在操作级返回明确错误，不降级到 `Math.random()`。
- [折叠导航可能隐藏用户想直接访问的工具] → 分类按钮保持固定顺序和清晰展开状态，选择新分类只需一次操作，移动端仍展示完整横向导航。

## Migration Plan

1. 先引入共享随机、编码和对称密码适配层及其测试，不接入导航。
2. 加入三个界面模块和样式，再扩展统一分组定义，使两个新分组出现在非对称加密前。
3. 执行单元、组件、类型、lint 和生产构建验证，并在桌面/窄视口手动核对导航和表单联动。
4. 以一次普通前端版本发布；无数据迁移或服务端变更。

若发布后出现问题，可移除新增导航项和功能模块并回退新增依赖；现有六个工具及 RSA 默认行为没有数据迁移依赖，可独立恢复。
