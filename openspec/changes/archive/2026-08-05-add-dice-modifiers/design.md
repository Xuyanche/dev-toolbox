## Context

现有骰子域模型以 `DicePool` 作为表达式解析和投掷的唯一配置，解析器按 `+` 分割并只接受 `NdS` 项；`DiceRoll.total` 只累加骰子点数。`DiceSimulatorTool` 同步骰子池与规范化表达式，并保留上一次 `DiceRoll` 作为独立结果快照。具体行为见 `specs/dice-simulator/spec.md`。

## Goals / Non-Goals

**Goals:**

- 用一个域配置同时表示骰子池和净整数补正，避免表达式、可视输入与投掷使用不同来源。
- 使表达式解析具有明确的项类型和符号规则，不依赖 JavaScript 表达式求值。
- 保留已完成投掷的补正与总点数快照，使后续配置编辑不改写历史结果。

**Non-Goals:**

- 不实现乘除、括号、骰子保留/重投、优势劣势或任意代数表达式。
- 不允许纯补正、无骰子的投掷。
- 不改变骰子面数、数量限制或随机生成方法。

## Decisions

### 引入包含骰子池和补正的配置类型

定义类似 `{ pool: DicePool, modifier: number }` 的 `DiceConfiguration`，让表达式解析器返回完整配置，格式化器也接收完整配置。页面可以使用一个配置状态，或保留分开状态但必须通过相同配置辅助函数格式化；关键是每次应用、可视编辑和投掷都以同一对 `pool + modifier` 为边界。

备选方案是保持 `parseDiceExpression` 只返回骰子池，再用第二个解析过程提取数字。该方案会重复扫描文本，也容易在错误边界和规范化上产生分歧，因此不采用。

### 使用项级扫描器而不是求值器

解析器按顺序读取 `+`/`-` 符号与后续项，将项分为 `NdS` 骰子项或十进制整数项。对骰子项，只接受隐式正号或 `+`；对整数项，将符号应用后累加到补正。扫描必须消费全部非空白输入，因此 `*`、`/`、括号、小数、连续运算符或尾随运算符会显式失败。所有数字及补正累加的中间/最终结果都检查 `Number.isSafeInteger`。

备选方案是清洗文本后使用 `eval` 或 `Function`。这会扩大可执行语法、带来安全问题，且无法准确禁止负骰子，因此严格不使用。

### 规范化表达式只保留一个净补正

格式化器先按现有固定面数顺序输出非零骰子池，然后在补正为正数时追加 ` + N`，为负数时追加 ` - abs(N)`，为 0 时不追加。这延续现有“应用后合并同面骰子”的规范化行为，并为可视补正编辑提供唯一稳定文本。

### 将补正写入投掷快照

`DiceRoll` 增加 `modifier`，并可选择增加 `diceTotal` 便于测试与显示；`total` 固定表示 `diceTotal + modifier`。投掷函数在创建结果时复制当前补正，结果区只读取 `DiceRoll` 而不读取正在编辑的配置，因此修改补正或“清空色子”不会追溯改写已有投掷。

### 将补正框作为选择区的独立紧凑列

在骰子网格与补正框外增加一层布局容器：桌面宽度下为“弹性骰子网格 + 紧凑补正列”，窄视口下改为单列。补正使用 `type=number` 与 `step=1`，但仍在状态边界严格检查安全整数，不依赖浏览器输入类型作为唯一校验。对补正 0，输入可显示空值或 `0`，两者都映射为同一域值。

## Risks / Trade-offs

- [表达式中骰子面数和纯整数项都以数字开头] → 以项内是否包含 `d`/`D` 严格区分类型，并要求每项完整匹配对应语法。
- [多个超大整数项在累加时溢出安全整数] → 每次累加后立即检查，失败时保留上一个有效配置。
- [超大补正与骰子和相加可能越过安全整数] → 投掷结束时检查最终总点数；若不安全则返回明确错误而不显示不精确结果。
- [编辑补正时输入框可短暂出现空字符串] → 将空值明确视为 0，其他不完整/无效字符串不提交到域配置。
- [新布局可能挤压现有七个骰子框] → 骰子网格保持 `minmax` 和自动换行，补正列使用受控紧凑宽度，并在窄屏断点下回流。

## Migration Plan

1. 扩展骰子配置、解析/格式化与投掷结果类型，保留无补正调用的默认 0 语义。
2. 将页面状态、补正输入、表达式同步和结果行接入新配置，然后增加桌面/窄屏样式。
3. 运行骰子域与组件测试、全量回归、类型/静态检查和生产构建。该变更不含持久化数据，回滚只需还原域类型、UI 与样式。
