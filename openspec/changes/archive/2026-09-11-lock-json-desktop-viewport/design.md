## Context

参见 [proposal.md](./proposal.md) 的动机和范围。当前应用壳层只设置 `min-height: 100vh`，主内容使用固定上下内边距，而编码和密码工具分别通过固定最小高度或 `calc(100dvh - offset)` 估算工作区高度。活动工具之后的全局页脚还会增加外层文档高度，因此即使部分文本框和结果区域已经内部滚动，页面仍可能出现纵向滚动条。

所有工具组件同时保留在 DOM 中并通过父级 `section[hidden]` 切换可见性，所以仅依靠后代选择器无法可靠判断当前活动工具。JSON 已实现的活动状态类和高度链可以作为基础，但需要推广到 AES、DES、SM4、URL、Unicode、Base64 和 JWT，并为不同页面结构提供适配。现有单列回退断点为 `980px`，规范保证的桌面验收视口为至少 `1280×768`。

## Goals / Non-Goals

**Goals:**

- 建立从应用壳层、主内容、活动工具到各目标工作区连续且可收缩的高度约束链。
- 只在对称加密或编码分组的目标工具处于活动状态且视口空间足够时锁定外层滚动。
- 让标题、参数或模式区、主要操作和全局页脚占据必要高度，功能工作区获得剩余高度。
- 在长输入、输出、大型树或工具固定内容无法继续收缩时，只滚动对应功能区域。
- 让低空间和全局警告场景自动回到可访问的自然文档流。

**Non-Goals:**

- 不把无外层滚动布局推广到随机数、非对称加密、摘要、时间工具或首页。
- 不重新设计任何目标工具的操作、参数、结果内容或侧边栏。
- 不在移动端引入输入与树形结构页签。
- 不隐藏全局页脚，也不改变全局能力警告的内容或触发规则。

## Decisions

### 1. 由应用活动状态显式标记目标工具聚焦模式

应用壳层维护明确的聚焦工具集合，包含 AES、DES、SM4、URL、Unicode、Base64、JWT 和 JSON。仅当集合中的工具处于活动状态且没有正在显示的全局能力警告时添加通用聚焦类；切换到首页或其他工具后立即移除。DES 等运行时关闭的工具只在实际启用并选中后参与判断。

选择显式工具集合而不是按导航分组名称或 `:has(...)` 推断，是因为非活动工具仍存在于 DOM 中，且运行时配置会改变可见工具。也不通过组件副作用修改 `body` 类名，避免全局状态清理和测试隔离问题。

### 2. 仅在宽度和高度均足够时锁定一个动态视口

聚焦样式放在同时满足双列宽度和最小桌面高度的媒体条件中；实现应覆盖 `1280×768` 验收视口。匹配时，应用壳层使用 `height: 100dvh`、`min-height: 0` 和 `overflow: hidden`，主内容使用同高的纵向弹性布局，当前活动工具 section 成为唯一允许承载工具级纵向溢出的区域。未匹配媒体条件或存在全局能力警告时，不启用外层溢出限制，继续使用当前自然文档滚动。

选择 `100dvh` 而不是 `100vh`，使高度跟随浏览器实际动态视口。选择由媒体条件关闭聚焦模式，而不是在所有尺寸上强制 `overflow: hidden`，可以让浏览器缩放、字体放大和低高度窗口通过 CSS 视口变化自然进入安全回退。

### 3. 用共享高度链和按工具适配替代像素偏移估算

聚焦模式下，当前活动工具容器和工具页建立 `height: 100%`、`min-height: 0` 的纵向弹性链。通用活动 section 使用内部 `overflow-y: auto` 作为最终可访问性兜底，避免任何工具固定内容被裁切。各页面再使用现有结构提供更细粒度的滚动：JSON 工作区弹性占满剩余空间，输入和树分别滚动；JWT 模式及主工作区弹性伸缩，长 Header、Payload 和令牌在正文区域滚动；URL、Unicode、Base64 的双列工作区弹性伸缩，两个文本框滚动；AES、DES、SM4 增加稳定页面钩子，参数面板保留，明密文双列区域弹性伸缩并由文本框滚动。DES 旧算法警告属于工具内容，继续保留在可滚动功能区域内。

选择“共享壳层约束 + 工具级适配”而不是单一固定高度，是因为各工具的标题、参数、警告、操作和状态区域差异明显；统一 `calc(100dvh - Npx)` 无法覆盖所有组合。活动 section 的内部滚动兜底可以在字体放大但媒体条件仍命中时保持所有控件可达。

### 4. 页脚保留在视口内并在聚焦模式中压缩留白

全局页脚作为主内容纵向布局中的不可收缩尾部保留。聚焦模式仅缩小其顶部外边距和内边距，保持现有文案、边框和语义。当前活动工具区域占据页脚之外的剩余高度。

选择保留紧凑页脚而不是隐藏它，可以维持现有全局本地处理与隐私信息；相比绝对定位页脚，正常弹性流也不会覆盖 JSON 面板或依赖手工预留空间。

### 5. 结构测试和真实浏览器尺寸检查分别验证不同风险

组件测试验证八个目标页面均获得聚焦类、首页与非目标工具会移除该类，以及出现全局能力警告时不启用该类。各工具测试验证其弹性工作区和内部滚动布局钩子。由于 JSDOM 不执行真实布局，实施验收还需在构建后的浏览器页面中，以 `1280×768` 和 `1440×900` 逐一检查目标页面的文档滚动高度不超过视口高度，并用超长内容确认内部功能区域可滚动；窄视口和低高度视口则检查文档滚动恢复。

选择明确区分结构测试与浏览器验收，而不是用 JSDOM 的尺寸属性模拟布局断言，可以避免产生无法发现真实溢出的伪回归测试。本次不为单一布局变更增加新的端到端测试依赖。

## Risks / Trade-offs

- [部分工具工作区在接近最小高度时会比当前固定最小值更矮] → 以媒体高度门槛控制聚焦模式，为文本区域保留可用最小高度，并以活动 section 内部滚动兜底。
- [遗漏某一级 `min-height: 0` 会使弹性子项拒绝收缩并再次产生溢出] → 对壳层、主内容、活动 section、工具页和工作区逐层检查，并用真实浏览器的 `scrollHeight` 验收。
- [多种内部滚动区域可能让滚轮目标不够直观] → 优先让文本框和结果正文滚动，只在固定内容无法容纳时使用整个活动工具区域的兜底滚动。
- [全局能力警告会占用不可预测高度] → 显示任何此类警告时不启用聚焦模式，优先保证警告和全部工具控件可访问。
- [页脚压缩后视觉节奏与非目标工具略有差异] → 将样式限定在通用聚焦类下，不改变其他页面，并保留相同文案、边框和排版基础。

## Migration Plan

1. 将现有 JSON 专用聚焦状态推广为目标工具集合驱动的通用聚焦状态。
2. 复用桌面高度与宽度媒体条件下的视口锁定和紧凑页脚，并补充通用活动 section 滚动兜底。
3. 为对称加密、文本编码和 JWT 工作区增加弹性高度及内部滚动适配，保持现有窄视口规则优先恢复自然高度。
4. 补充八个目标页面、非目标页面、全局警告和回退视口测试。
5. 运行组件测试、类型检查、代码检查和生产构建，并完成目标视口与回退视口的浏览器布局验收。

回滚扩展部分时可将通用工具集合恢复为仅 JSON 并移除新增工具适配；所有数据和操作逻辑均不需要迁移。
