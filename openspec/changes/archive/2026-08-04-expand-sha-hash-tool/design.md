## Context

现有摘要领域层以同步 `calculateMd5` 和异步 `calculateSha1` 返回统一的大小写十六进制结果；SHA-1 使用 Web Crypto。`HashTool` 通过 `MD5 | SHA-1` 参数复用同一套单结果页面，应用壳使用内部工具 ID `sha1`，首页和两种导航均显示 `SHA-1`。当前依赖已覆盖 MD5，浏览器 Web Crypto 原生支持本次选定的四种 SHA 算法。

## Goals / Non-Goals

**Goals:**

- 对同一 UTF-8 输入并行计算四种 SHA，并只发布完整、同源的一批结果。
- 以数据驱动方式统一算法标签、Web Crypto 名称、预期十六进制长度和结果渲染。
- 保留 MD5 页面现有行为，同时让 SHA 页面适合多个长摘要在桌面与窄屏中阅读和复制。
- 清除代码、首页和导航中的用户可见 `SHA-1` 工具名称残留。

**Non-Goals:**

- 不增加 SHA-224、SHA-3、SHAKE、HMAC、文件摘要或流式大文件处理。
- 不提供算法勾选、自定义输出编码或摘要截断。
- 不将 SHA-2 描述为密码哈希或替代专用密码派生算法。
- 不改变 MD5 的计算结果、导航位置或清空语义。

## Decisions

### 1. 用固定算法清单驱动一次性 SHA 批次

领域层定义稳定顺序的 SHA 元数据清单：SHA-1、SHA-256、SHA-384、SHA-512。批次函数把输入只编码一次，然后以 `Promise.all` 调用 Web Crypto，所有计算成功后才构造以算法标识索引的 `DigestVariants` 结果。

相比依次等待四次计算，并行调用减少总等待时间；相比边完成边更新页面，原子批次避免同一结果区混入不同输入或只显示部分算法。若任一算法失败，函数返回单一可理解错误且不返回部分结果。

### 2. 继续使用 Web Crypto，不新增哈希依赖

四种目标算法均属于 Web Crypto `SubtleCrypto.digest` 的标准支持集合，现有应用也已经为 SHA/RSA 检查该能力。继续使用浏览器原语可以避免增加包体积或在 Web Crypto 与第三方实现之间产生语义差异。

备选方案是统一改用现有 `@noble/hashes`，可降低对 `crypto.subtle` 的依赖，但会改变当前 SHA 执行路径和全局能力提示，并没有为本次四算法范围带来必要收益，因此不采用。

### 3. SHA 页面使用单列紧凑算法组与内嵌复制图标

`HashTool` 的公开参数保持 `MD5 | SHA`。MD5 继续沿用两块结果面板；SHA 分支保存完整批次，并按元数据清单将 SHA-1、SHA-256、SHA-384、SHA-512 四个算法组从上到下渲染为单列。算法组减少面板内边距、标题间距和结果行间距，以降低每种算法占用的纵向空间。

每个算法组包含小写与大写两条紧凑结果行。每行使用“固定宽度变体标签 + 可伸缩摘要内容框 + 内容框右端图标按钮”的布局，让“小写摘要”或“大写摘要”与对应值保持在同一水平行。摘要内容框负责长文本换行；复制值始终使用未截断的完整摘要。

复制操作使用项目内联 SVG 复制图标，不显示按钮文字。按钮在视觉上与摘要框右端整合，但仍保留独立的原生 `button` 语义、键盘焦点样式、明确的 `aria-label` 和可选 `title`。复制成功或失败反馈放在不会挤压摘要行的独立 live region 中，避免反馈出现时改变行高或按钮位置。

相比两列算法卡片，固定单列能保持 SHA 输出长度逐级增长时的阅读顺序和可用宽度；相比将复制按钮放在标题旁，内嵌图标减少视觉噪声并使操作目标紧邻其对应摘要。

### 4. 将内部工具 ID 一并从 `sha1` 改为 `sha`

应用没有持久化或 URL 路由依赖工具 ID，因此直接把内部标识改为 `sha`，同时更新显示名称、短说明、图标、首页概览、浏览器能力提示和测试期望。这能避免未来代码继续把多算法页面误认为 SHA-1 专用页。

保留旧 ID 虽然改动更少，但会让状态、测试选择器和维护语义持续漂移，因此不采用。

### 5. 安全提示按用途区分

MD5 页面保留旧算法警告。SHA 页面使用两段式提示：SHA-1 已不适用于需要抗碰撞性的安全用途；SHA-256/384/512 可用于常规完整性摘要，但不应直接用于密码存储。提示不阻止计算，因为工具仍需要支持兼容性核对。

## Risks / Trade-offs

- [四次 Web Crypto 调用增加短输入的固定开销] → 并行执行且只编码一次；界面复用单一忙碌状态防止重复提交。
- [SHA-512 大小写结果很长，八个输出可能增加页面高度] → 四个算法组固定单列但采用紧凑结果行、减少面板留白，并允许摘要内容框安全断行且保持复制内容完整。
- [仅使用图标可能降低复制操作的可发现性或可访问性] → 使用通用复制图形、悬停提示、明确的可访问名称和可见键盘焦点，反馈通过独立 live region 呈现。
- [某些旧环境缺少目标算法实现] → 复用全局能力提示，批次失败时清空旧结果并显示统一错误，不静默降级或返回部分批次。
- [把 `sha1` ID 改为 `sha` 可能影响测试或组件状态] → 当前 ID 不持久化；集中更新静态工具定义和导航测试，并执行跨工具状态回归。

## Migration Plan

1. 扩展摘要领域类型和批次计算函数，并用标准向量覆盖四种算法、空文本和失败路径。
2. 将 SHA 页面改为四算法单列紧凑结果组，将复制图标整合到每条摘要框右端，并补充复制、清空、忙碌和响应式测试。
3. 更新工具 ID、导航标签、首页概览与能力提示，并执行桌面/移动导航回归。
4. 运行完整测试、类型检查、Lint、生产构建和严格 OpenSpec 校验。

回滚时可恢复 `calculateSha1`、单结果页面和 `sha1` 工具定义；没有持久化状态或数据迁移需要处理。
